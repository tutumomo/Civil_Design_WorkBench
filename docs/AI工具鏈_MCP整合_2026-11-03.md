## 1. 為什麼會誤判「Blender 未安裝」

**根因**：`tools\project_paths.py::blender_exe()` 只找

- 環境變數 `BLENDER`
- `PATH` 上的 `blender`
- `C:\Program Files\Blender Foundation\Blender *\blender.exe`

本機 Blender 是 MSIX 套件，exe 實際位置：

```
C:\Program Files\WindowsApps\BlenderFoundation.Blender_5.2.3.0_x64__ppwjx1n5r4v9t\Blender\blender.exe
```

`WindowsApps` 不在上述任一搜尋路徑，因此 `blender_exe()` 回傳 `None`，所有「環境自檢」就跟著寫「Blender 未安裝」。

**修法（已套用）**：`blender_exe()` 改為

1. `BLENDER` / `CIVIL_AI_BLENDER` 環境變數
2. **呼叫 `tools\blender\blender_runner.find_blender()`**（用 `Get-AppxPackage` 解析 MSIX `InstallLocation`）
3. `C:\`／`D:\Program Files\Blender Foundation`
4. `PATH`

並加模組級快取（`_BLENDER_CACHE`），避免每次自檢都跑一次 PowerShell。
修完後 `project_paths.report()["blender"]` 已正確回傳 MSIX 路徑。

**教訓（給未來的自檢腳本）**：只要應用是 Store 版（Blender、部分 Python、Terminal），
「檔案不存在」不能推論「未安裝」，要查 `Get-AppxPackage`。

## 3. Orkas 內建連接器（本對話可直接呼叫）

本 App 沒有「寫檔註冊」的 API，只能用 `add_custom_connector` 走 MCP 協定實際連上線，結果：

| 顯示名 | 連接器 id | 工具數 | 用途 |
|---|---|---|---|
| CivilRegs | `custom-civilregs` | 9 | 規範查詢（`regs_ask` 等） |
| BlenderCivil | `custom-blendercivil` | 5 | Blender 場景／渲染 |
| AutoCADPro | `custom-autocadpro` | 65 | AutoCAD 繪圖（`lean` 檔） |
| ArtCraft | `custom-artcraft-2` | 5 | 15 套 CLI 閘道 |
| CadGen | `custom-cadgen` | 2 | CAD Viewer 連結 |

### 3.1 踩到的三個坑

1. **名稱限制**：顯示名只允許 `字母、數字、空白、. _ / -`（≤64 字）。
   `CivilRegs` 通過；含全形括號或 `／` 會直接被拒。
2. **環境變數確實會傳給子程序**（實測）：`ARTCRAFT_WORK_DIR=D:\Civil_Design_WorkBench\out`
   之後，`cadcraft-cli sample ... _temp/x.dxf` 產生 `out\_temp\x.dxf`，不再落到 `D:\公司案件`。
   舊連接器是用錯變數名（`ARTCRAFT_WORKDIR`）才寫錯地方；`server.py` 已改成兩種名稱都吃。
3. **殺掉 gateway 程序後連接器變 `Not connected`**，且不會自動復活。
   解法：用 `add_custom_connector` 重新加一次（會產生新 id，如 `custom-artcraft-2`），
   再把舊的失效記錄從 `%ORKAS_DATA%\cloud\config\connectors.json` 移除（**先備份**）。

| 連接器 | 實測呼叫 | 結果 |

### 3.2 相對路徑規則（重要）

ArtCraft 閘道的 `WORK_DIR` 已綁到 `out\`。所以從 MCP 呼叫 ArtCraft 時：

- 想產交付物 → 給 `_temp/xxx.dxf`（會變 `out\_temp\xxx.dxf`）
- 想產正式檔案 → 給 `案件名/xxx.pdf`（會變 `out\案件名\xxx.pdf`）
- **不要**給 `..\` 或絕對路徑以外的相對跳脫，會被解析到 `out` 之外或被拒。

