# 交付閘門總表

> 2026-10-28｜一份 `case.json` 要走到「可交件」，中間要過幾道機器閘門。
> 這張表是為了回答一個問題：**如果有人問「你這份圖／這份預算能不能交」，憑什麼說能？**

## 一、六道閘門

| # | 閘門 | 檢查什麼 | 不過的後果 |
|---|---|---|---|
| 0 | **案名／主辦機關確認** | 報告書輸出前必須先向使用者確認案名（`project.full_name`）與主辦機關（`project.agency`），不得空白或含「待填／請填／TBD」 | `make_report.py` **exit 4**，不產任何檔（內部測試須明確加 `--allow-placeholder`） |
| 1 | **設計檢核** | 擋土牆滑動／傾倒／合力作用點／承載 FS；邊坡無限邊坡＋圓弧 FS；排水溝 8 項水力檢核 | `case_core check` **error** → 全軸中止 |
| 2 | **E1~E18 品管** | 字高（本文3／附註4／標題5 mm）、標準比例、文字疊字、視口超框、圖層齊備、標題欄與技師圖記區零跨越、顏色→線粗（E17）、出圖型式（E18） | `check_delivery` exit 1 |
| 3 | **圖／數對帳** | 圖上量到的混凝土淨面積 ＝ 數量模型斷面積（容許 0.5%）；道路刨鋪多邊形面積 ＝ `area_m2`（容許 1%） | section／drawing 軸 fail |
| 4 | **配筋圖核算** | 配筋圖鋼筋圓點間距 ＝ 配筋設計間距 | section 軸 fail |
| 5 | **設計段落注入** | `case_core._design_sections` 是否拋錯（拋錯會讓第 6/7/8/9/11 章整批消失） | 報告軸 exit 1 |
| 6 | **全案回歸** | 六案三大軸 ＋ 關鍵數值與 `baseline.json` 比對 | `regression.py` exit 1 |

## 二、各閘門各自防什麼（互不重疊）

| 閘門 | 防的是 | 抓不到什麼 |
|---|---|---|
| 0 案名／主辦機關 | **把「待填」的封面交出去**（封面是交件第一眼，錯了整套退） | 名稱填錯（打字錯誤驗不到） |
| 1 設計檢核 | **算出來不成立**（斷面不夠、坡度太陡） | 圖畫錯、數量算錯 |
| 2 E1~E18 | 圖面格式錯（字太小、比例非標準、疊字、缺圖層、線粗不分級、出圖型式不是 monochrome） | 數字對不對 |
| 3 圖／數對帳 | **圖畫得好看但數量算錯**（內腔沒扣、多邊形重複） | 設計成不成立 |
| 4 配筋核算 | **設計改了圖沒更新** | 數量與預算 |
| 5 設計段落注入 | **計算成功但沒進到報告**（`%d` 收到 None 之類） | 算得對不對 |
| 6 回歸 | **這次改動讓別案退步** | 新案本身的問題 |

> **E17／E18 是 2026-10-29 補的**：出圖規定新增「autocad 出圖樣式」後，顏色與線粗不再只是好看，
> 而是可被機器比對的規格；安裝版 monochrome.ctb 的線粗與規定不同，所以專案自帶一份 CTB。
> 說明見 [`出圖樣式與線粗.md`](出圖樣式與線粗.md)。

> **第 5 道是 2026-10-28 補的**：一句 `%d` 收到 `None`，讓 `_design_sections` 拋錯，
> 第 6/7/8/9/11 章整批消失，而報告工具照樣 exit 0、全軸照樣「全部通過」。
> 現在會讀 `report_case.json` 的 `_derived.design_sections_error`，有值即失敗。
> 負面測試：插入 `raise RuntimeError` → `[FAIL] 設計報告 exit=1`、整體「有未通過項目」。

## 三、實際抓過的錯（閘門的戰績）

| 閘門 | 抓到的真實錯誤 |
|---|---|
| 0 | 六個示範案件的 `agency` 全是「（主辦機關待填）」，報告書照樣完稿交件（2026-11-02 補閘門） |
| 1 | 合力作用點 0.6499 vs 0.65 —— 邊界浮點誤差（已加 0.05% BL 容差） |
| 2 | 4 m 高擋土牆在 1:20 下視口 261 mm 超出 A3 可用區 249 mm（3 m 牆剛好放得下，所以先前從未暴露） |
| 3 | 排水溝內腔多邊形**畫了兩次** → 淨面積 0.375 變 0.015（差 96%），E1~E18 完全看不出來 |
| 3 | 道路刨鋪範圍**未裁樁號** → 多算 7.57%（915.0 vs 851.1 m²） |
| 4 | 牆身 0.35→0.30 但配筋圖沒重出 → 圖面 220 vs 設計 270 |
| 5 | 回歸自己第一版讀 `r["FS_sliding"]`（不存在的鍵）被 `except` 吞掉，基準只剩斷面積而輸出照樣「全部相符」 |

## 四、閘門之外的（機器驗不到，必須人看）

| 項目 | 為什麼機器驗不到 |
|---|---|
| 單價是否為當期行情 | 價格會變；工具只能標「物價庫／假設值」與**查證覆蓋率** |
| 土工參數（γ／φ／c） | 需鑽探報告；工具用假設值並要求重算 |
| 技師簽證與圖記 | 法定行為 |
| 施工可行性、現場條件 | 需現地判斷 |
| 報告敘述是否通順 | 人工複核（標「需人工補」的章節） |

## 五、一句話

**六道閘門擋的是「機器能證明的錯」；剩下的靠人。**
把前者自動化，人的注意力才能留給後者。
