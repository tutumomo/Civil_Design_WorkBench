> 2026-10-28 建立｜預算書最容易出問題的不是算術，是**單價**
> 而單價往往混了兩種東西：從營建物價抄來的（有來源）、自己填的（沒有來源）。
> 兩者印在同一張詳細表上一模一樣，讀的人看不出哪一項可信。

## 2. 單價來源稽核（`tools\boq\price_audit.py`）

逐項比對價格庫，標出「物價庫」還是「假設值」，並算出**查證覆蓋率**。

```bat
python tools/boq/price_audit.py cases/AC刨鋪5cm工程/case.json
```

比對方式：先比**資源代碼**，沒有代碼時用**名稱前 8 字**比對（價格庫名稱含更細的規格）。

### 實測四案

| 案件 | 查證覆蓋率 | 說明 |
|---|---|---|
| AC刨鋪5cm工程 | **42.9%**（3／7） | 刨除 0296140032、黏層 0274711002、瀝青舖面 02742132A5 |
| 擋土牆3m重力式 | **0.0%**（0／9） | 工作區無擋土牆單價資料 |
| 擋土牆3m懸臂式 | **0.0%**（0／9） | 同上 |
| 排水溝U型 | **0.0%**（0／8） | 工作區無排水溝單價資料 |

**0% 不是 bug，是事實** —— 工作區的 `20250619 營建物價查詢` 只有路面與標線兩類。

### AC 案那 4 項為什麼對不上

| 工項 | 為什麼 |
|---|---|
| 施工測量及放樣（式） | 一式計價，物價庫無此工項 |
| 標線復舊（式） | 物價庫有「標線 M2」，但案件是「復舊 一式 8,000」，單位不同無法換算 |
| 交通維持及安全設施（式） | 物價庫無此工項 |
| 機具進出場費（式） | 物價庫無此工項 |

→ 一式計價的項目本來就難有市價可查，屬於「需依經驗與廠商報價」的類別。這個事實應該寫在交付清單上，而不是讓它靜靜混在整齊的表格裡。

## 3. 已接進交付包

`case_package.py` 跑完預算軸後自動執行稽核，寫出 `<案名>_單價來源稽核.md`，並在交付清單加一節：

```
## 一之二、單價查證覆蓋率

- **42.9%**（3／7 項取自營建物價 11405，4 項為假設值）
- 逐項稽核：`AC刨鋪5cm工程_單價來源稽核.md`
- 假設值不必然錯，但它沒有查證；正式預算前應逐項詢價或補進 `tools\boq\prices\`。
```

---

## 4. 踩到的兩個坑

1. **案件工項原本沒有 `code` 欄** → 覆蓋率一律 0%，因為比對不到。補上 3 項代碼後才有 42.9%。
   → **價格庫與案件之間沒有 key，就等於沒有連結。**
2. **稽核輸出的 Markdown 粗體 `**` 讓交付清單的正則抓不到數字** → 覆蓋率那節整段消失，但看起來一切正常（清單照樣產出、照樣「全部通過」）。正則要容許標記符號。

---

## 5. 怎麼補覆蓋率

| 類別 | 來源 |
|---|---|
| 擋土牆（混凝土／鋼筋／模板／開挖／背填） | 需向營建物價查詢「擋土牆工程」或廠商報價 |
| 排水溝（混凝土／模板／開挖／預鑄溝） | 同上，或查預鑄 U 型溝型錄 |
| 標線復舊 | 可用「標線 M2」× 實際面積換算，取代一式 |
| 一式項目（測量／交維／進出場） | 依經驗值或廠商報價，難以查證 |

補進 `tools\boq\prices\` 後，在案件的 `boq.items` 加 `code`，覆蓋率就會自動上升。
