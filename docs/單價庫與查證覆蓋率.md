> 2026-10-28 建立｜預算書最容易出問題的不是算術，是**單價**

> 兩者印在同一張詳細表上一模一樣，讀的人看不出哪一項可信。

## 2. 單價來源稽核（`tools\boq\price_audit.py`）

逐項比對價格庫，標出「物價庫」還是「假設值」，並算出**查證覆蓋率**。

```bat
python tools/boq/price_audit.py cases/AC刨鋪5cm工程/case.json
```

比對方式：先比**資源代碼**，沒有代碼時用**名稱前 8 字**比對（價格庫名稱含更細的規格）。

### 實測十案（2026-11-26 複測）

| 案件 | 查證覆蓋率 | 說明 |
|---|---|---|
| AC刨鋪5cm工程 | **71.4%**（5／7） | 刨除 0296140032、黏層 0274711002、瀝青舖面 02742132A5 等 |
| 排水溝U型 | **62.5%**（5／8） | 開挖／混凝土／模板／背填／鋼筋對上價格庫 |
| 擋土牆3m重力式 | **55.6%**（5／9） | 同上 |
| 擋土牆3m懸臂式 | **55.6%**（5／9） | 同上 |
| 擋土牆4m半重力式 | **55.6%**（5／9） | 同上 |
| 邊坡5m生態護坡 | **60.0%**（3／5） | 開挖／植生／排水 |
| 箱涵三孔測試 | **12.5%**（1／8） | 箱涵工項多為自組工項，價格庫沒有對應品項 |
| 擋土牆6m加勁式 | **0.0%**（0／11） | 加勁材、錨定、排水孔等工項未登資源代碼 |
| 擋土牆7m錨定式 | **0.0%**（0／11） | 同上（地錨、鑽孔） |
| 擋土牆8m扶壁式 | **0.0%**（0／9） | 同上（扶壁、繫筋） |

> **覆蓋率 0% 不是 bug，是事實** —— 該案工項沒有登資源代碼，比對不到就一定 0%。
> 補代碼即上升，見 §5。

> ⚠ **覆蓋率只算「對得上價格庫」，不算「價格一致」**。稽核另標「⚠ 不符」：
> 資源代碼對得上但單價與價格庫不同（例：擋土牆 3 m 重力式有 5 項不符）。
> 交付前須逐項確認是「契約別單價」還是「填錯了」。

### AC 案那 4 項為什麼對不上

| 工項 | 為什麼 |
|---|---|
| 施工測量及放樣（式） | 一式計價，物價庫無此工項 |
| 標線復舊（式） | 物價庫有「標線 M2」，但案件是「復舊 一式 8,000」，單位不同無法換算 |
| 交通維持及安全設施（式） | 物價庫無此工項 |
| 機具進出場費（式） | 物價庫無此工項 |

→ 一式計價的項目本來就難有市價可查，屬於「需依經驗與廠商報價」的類別。這個事實應該寫在交付清單上，而不是讓它靜靜混在整齊的表格裡。

## 3. 已接進交付包

`case_package.py` 跑完預算軸後自動執行稽核，寫出 `<案名>_單價來源稽核.md`，並在交付清單加一節：

```
## 一之二、單價查證覆蓋率

- **71.4%**（5／7 項取自價格庫，2 項為假設值）
- 逐項稽核：`AC刨鋪5cm工程_單價來源稽核.md`
- 假設值不必然錯，但它沒有查證；正式預算前應逐項詢價或補進 `tools\boq\prices\`。
```

---

## 4. 踩到的兩個坑

1. **案件工項原本沒有 `code` 欄** → 覆蓋率一律 0%，因為比對不到。補上代碼後覆蓋率才會上升。
   → **價格庫與案件之間沒有 key，就等於沒有連結。**
2. **稽核輸出的 Markdown 粗體 `**` 讓交付清單的正則抓不到數字** → 覆蓋率那節整段消失，但看起來一切正常（清單照樣產出、照樣「全部通過」）。正則要容許標記符號。

## 5. 怎麼補覆蓋率

| 類別 | 來源 |
|---|---|
| 擋土牆（混凝土／鋼筋／模板／開挖／背填） | 已補「公路總局單價分析表」＋大雅區開口契約；差額項仍需廠商報價 |
| 排水溝（混凝土／模板／開挖／預鑄溝） | 同上；預鑄溝需查型錄 |
| 加勁材／地錨／鑽孔／扶壁（加勁、錨定、扶壁式） | 仍無資源代碼，需向廠商報價並登代碼 |
| 標線復舊 | 可用「標線 M2」× 實際面積換算，取代一式 |
| 一式項目（測量／交維／進出場） | 依經驗值或廠商報價，難以查證 |

補進 `tools/boq/prices/` 後，在案件的 `boq.items` 加 `code`，覆蓋率就會自動上升。

> **「⚠ 不符」是另一個問題**：代碼對得上但單價不同時，覆蓋率仍算已查證。
> 稽核輸出會列出不符的項次，交付前要逐項確認是「契約別單價」還是「填錯了」。
