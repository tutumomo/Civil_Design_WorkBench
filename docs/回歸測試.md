# 全案回歸測試（`tools/selftest/regression.py`）

> 2026-10-28 建立｜工具改一次就得手動跑全案全軸，靠人記得跑，遲早漏掉 ——
> 而漏掉的那一次，通常正好是改壞的那一次。

## 1. 一條指令

```bat
C:\Python312\python.exe tools\selftest\regression.py            :: 比對基準
C:\Python312\python.exe tools\selftest\regression.py --update   :: 重寫基準（改了設計才用）
```

- 逐案跑 `case_package.py`（含出圖、預算、報告、三道對帳閘門）
- 收集關鍵數值，與 `tools\selftest\baseline.json` 比對
- 任一項不符 → 退出碼 1，列出「基準 → 現在」

> 回歸只證明「既有案件沒被改壞」。**新增或修改設計計算器**另有一道上架檢核
> （八關：引擎／目錄／範例／輸出形狀／條文／下拉／主題卡／標籤）：
>
> ```bat
> C:\Python312\python.exe tools\selftest\design_launch_check.py <id>
> ```
>
> 兩者不可互相取代；流程見 `docs\設計計算器上架SOP.md`。

## 4. 建立的過程中抓到的問題

### 4.1 `analyse()` 沒有扁平的 `FS_sliding` 鍵

`retaining_wall.analyse()` 回傳的是 `checks: [{item, value, limit, ok}]`，
沒有 `FS_sliding` / `FS_overturning`。第一版回歸直接讀 `r["FS_sliding"]` → `KeyError`
→ 整段設計數值被 `except` 吞掉，基準裡只剩斷面積。

**例外處理寫成 `except: pass` 會讓「沒抓到」看起來像「沒問題」。**

### 4.2 合力作用點卡在邊界（真實 bug）

抓 FS 時一併看到 `合力作用點（土層基礎，1/3 中段）` 是 **False**：

```
x_lo = 1.95 × (0.5 − 1/6) = 0.649999…
x_R  = 0.6499            → 判不合格（差 0.0001 m）
```

這是**邊界值 + 浮點誤差**，不是真的偏心。已加 0.05% BL 容差。

> 更值得注意的是：**這條檢核沒有任何交付閘門在管**。
> `check_delivery` 管圖面、`dxf_takeoff` 管圖數一致、配筋閘門管鋼筋排法 ——
> 但「設計檢核有沒有全部通過」一直只靠報告上印出來的那張表，沒有人擋。
> 這是下一個該補的閘門。

## 5. 什麼時候該跑

| 時機 | 為什麼 |
|---|---|
| 改 `tools/design/*` 任一計算模組 | 數字會變，要確認是「有意的變」 |
| 改 `qty_models` / `case_core` | 數量與派生會變 |
| 改繪圖模組 / `chapters.json` | 圖與報告會變 |
| 交付前 | 最後一次確認六案都還在基準上 |

**改了設計（斷面、流量、鋼筋）才用 `--update`**；只是重構程式不該改基準。
