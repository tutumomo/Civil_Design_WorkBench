> 來源：2026-11-11 整理 `CLAUDE.md` 時對程式庫的盤點。本計劃只處理**開發體驗與可維護性**，不改任何設計計算結果、不改交付物格式。

## 1. 目標與原則

- **目標**：縮短「改一行、驗一次」的回饋時間；讓測試能被自動執行；降低兩個超大檔的修改風險；消除文件與實際路徑不一致造成的誤導。
- **原則**
  1. 每一項獨立成一個 commit（或一組連續 commit），互不綁定，可單獨回滾。
  2. **數值不得變動**：除 W3 外，任何一項完成後 `regression.py` 必須在**不跑 `--update`** 的前提下通過。
  3. 重構類（W6、W7）採「只搬不改」：先搬移、測試全過，再談邏輯調整。
  4. `regression.py --update` 屬 ask-first，僅 W3 可能用到，且須先取得使用者同意。

## 3. 各項細節

### W1　`regression.py` 加 argparse 與 `--only`

- **現況**：`tools/selftest/regression.py` 以 `"--update" in sys.argv` 判斷旗標，沒有 argparse。實測 `regression.py --help` 會直接跑完 11 案；也無法只跑單一案件。
- **作法**
  1. 改用 argparse，保留既有 `--update`、`--ignore-new`，行為不變。
  2. 新增 `--only <案名>[,<案名>…]`：只跑指定案件，只比對這些案件的基準。
  3. `--only` 與 `--update` 併用時，只改寫指定案件的基準段落，其餘原樣保留。
  4. 新增 `--list`：列出 `cases/` 下會被掃到的案名後結束。
- **涉及檔案**：`tools/selftest/regression.py`、`docs/回歸測試.md`、`CLAUDE.md`（移除「`--help` 會全跑」的警告）。
- **驗收**
  - `regression.py --help` 一秒內印出說明、退出碼 0、不跑任何案件。
  - `regression.py --only 排水溝U型` 只出現該案一行，結果與全跑時該案一致。
  - 不帶參數全跑的輸出與退出碼和改動前相同。

### W2　`design_core_selftest.py` 支援篩選測試

- **現況**：`__main__` 用 `loadTestsFromModule` 後直接執行，忽略命令列參數。實測 `design_core_selftest.py WallRebarTests` 仍跑全部 158 個測試；目前只能 `cd tools/selftest` 後用 `-m unittest design_core_selftest.WallRebarTests` 繞過。

- **涉及檔案**：`tools/selftest/design_core_selftest.py`、`CLAUDE.md`、`docs/設計計算器上架SOP.md`（補單一類別跑法）。
- **驗收**
  - 不帶參數：158 個測試全過、退出碼 0。
  - `design_core_selftest.py WallRebarTests`：只跑 10 個。
  - 故意改壞一個斷言時退出碼為非 0（驗完還原）。

### W4　建立 CI

- **現況**：專案沒有 `.github/`，測試全靠人工或智能體記得跑。專案在多台電腦輪流作業，漏跑的機會高。
- **作法**
  1. **先確認哪些測試能在乾淨的 Linux runner 上跑**：`design_core_selftest.py`、`design_workbench_selftest.py`、`regq_selftest.py`、`regression.py` 各自是否依賴 OpenCADStudio、字型、`data/` 圖資或 `_regs_index.sqlite`（**尚未驗證**）。依賴外部工具者不進 CI，或以環境變數跳過並明確印出「已略過」。
  2. 新增 `.github/workflows/selftest.yml`：`push`／`pull_request` 觸發，Python 3.12，`pip install -r requirements.txt`，依序跑可行的測試。
  3. 加一個只在 `tools/design/**` 變動時才跑 `design_launch_check.py --all` 的 job。
- **涉及檔案**：`.github/workflows/selftest.yml`、`docs/回歸測試.md`、`README.md`（加狀態徽章，選用）。
- **驗收**：一次乾淨 push 為綠燈；故意推一個會失敗的分支為紅燈。
- **注意**：`data/` 內大型圖資與法規索引若未進版控，CI 內相關測試須有明確的略過路徑，不可靜默通過。

- 更換 CAD 後端或必備工具的版本來源。
- 把專案改成可 `pip install` 的套件（`sys.path` 慣例維持現狀；若日後要做，另立計劃）。
