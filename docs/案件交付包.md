# 案件交付包（tools\case_package）—— 三軸一鍵交付

> 2026-10-28 建立｜目標：**一份案件主檔 → 設計圖 ＋ 預算書 ＋ 設計報告 三軸一次跑完，並產出交付清單**
> 這是「全能土木設計助手」的入口層：三軸各自有自己的確定性工具，本層只負責串接與收集證據。

---

## 1. 三軸與各自的工具

| 軸 | 工具 | 驗證方式 | 退出碼意義 |
|---|---|---|---|
| **設計圖** | `tools\site_basemap` → `tools\a3_sheet\make_sheet.py --publish` → `tools\acad\acc.py` | `tools\a3_sheet\check_delivery.py`（E1~E18） | 0 = 可交件 |
| **預算書** | `tools\boq\boq_build.py` | xlsx 回讀總計＝計算值 ＋ `gridcraft-cli check` round-trip | 0 = 可交件 |
| **設計報告** | `tools\report\make_report.py` | 產檔 ＋ 內建驗證 ＋ 人工複核「需人工補」章節 | 0 = 已產出 |

`case_package` 不重新實作任何計算，只做三件事：**落檔、呼叫、收集退出碼**。工具升級時本層不必跟著改。

---

## 2. 用法

```bat
set PYTHONIOENCODING=utf-8

:: 三軸全跑（主檔有哪幾軸就跑哪幾軸）
python <專案根目錄>/tools/case_package/case_package.py ^
  <案件主檔.json> [--out-dir DIR] [--only boq,report,drawing] [--no-pdf]
```

退出碼：`0` = 啟用的每一軸都通過自己的驗證；`1` = 有未通過項目（交付清單會寫原因，`_log_<軸>.txt` 有完整輸出）。

### 主檔格式

```jsonc
{
  "title": "案名（輸出檔名與清單標題）",
  "out_dir": "輸出資料夾（可省略；預設 <專案根目錄>\\out\\<案名>，見 AGENTS.md 1.1）",

  // 三軸各自選用；下面三種寫法可混用
  "boq":    { ...boq_build 的案件 JSON 全文... },
  "boq_path": "tools/boq/examples/AC刨鋪5cm工程.json",
  "report": { ...make_report 的案件 JSON 全文... },
  "report_path": "tools/report/examples/AC刨鋪5cm工程.json",

  "drawing": {
    "dxf": "案名\\案名_現況平面圖_A3.dxf",
    "scale": 600,                       // 必須是標準比例尺（tools\drawing_rules.py）
    "require_dwg": true,
    "require_layers": ["10_道路邊線_現況", "20_建物"]   // 22_水道 無水道時才省略
  }
}
```

> **刻意設計成「超集」**：`boq` 段就是 `boq_build.py` 的輸入、`report` 段就是 `make_report.py` 的輸入，本層原樣落地到 `<out>\_case\` 再呼叫。這樣任一條產線的 schema 升級，本層不用改。

### 實測抓到的真問題（重要）

`大雅區六寶里現況平面圖` 的 A3 成果（2026-10-26 產製）**在今天的品管門檻下不合格**：
`check_delivery.py` 報 **E15 字高不符 29 處**（指北針「指 北」2.50 mm、比例尺數字 1.80 mm…），exit 1。
以現行 `make_sheet.py` 重出的樣本（`tools\a3_sheet\_selftest_rules`）則是 **0 錯誤**。

→ **結論：不是工具壞了，是舊交付物過期。** E15/E16 是 2026-10-27 才上線的規定；
所有在那之前產出的 A3 圖都必須重新產製並重跑 `check_delivery.py` 才能算交件。
該主檔保留為實例，重出會覆寫既有交付檔 → **須先取得使用者同意**。

## 5. 交件前人工必檢（工具做不到的，清單也印在交付清單裡）

1. 圖面：開 PDF 目視比例尺、指北針、標題欄填值、技師圖記區（E9 已機器檢，仍建議看一眼）
2. 預算書：工項名稱錯字、數量對得回圖面、單價是否當期行情（`note` 標「假設值，須詢價」者必須換掉）
3. 設計報告：所有標「需人工補」的章節（委託單位、業主、版次待核的法規）
4. **三軸數字一致性**：圖面數量（L／A／V）＝ 預算書數量 ＝ 報告數量表
5. 業主／設計／繪圖／日期四欄人工填寫並核章

## 6. 已知限制

| 限制 | 說明 |
|---|---|
| 三軸尚未共用同一份 JSON 的「同一段數字」 | 目前 `boq` 與 `report` 各自帶自己的 schema，數量要人工填兩次 → **下一步：加一層數量主表自動注入** |
| 設計圖軸不負責「產圖」 | 它只驗收既有 A3；產圖仍要跑 `site_basemap → make_sheet`（因需要經緯度與圖幅決策，交給人判斷範圍） |
| 沒有交付到 NAS 的動作 | 依 AGENTS.md §1，對外交付須使用者明確指示，工具刻意不做 |
| 報告章節內容仍需人工複核 | 產線只保證骨架與已提供資料正確，不保證論述品質 |

## 7. 統一案件檔（`civil-case/1`）—— **現行建議用法**

> 上方 §2 的「超集主檔」仍可用（向後相容），但**新案件請用統一案件檔**：
> 一份 `cases\<案名>\case.json` 同時驅動三軸，數量只寫一次，並由工具擋住矛盾。

### 7.1 為什麼

舊寫法三軸各吃自己的 JSON，同一個面積要打三次，打錯不會有任何工具報錯。統一案件檔把數量收斂成**唯一來源**：

| 機制 | 效果 |
|---|---|
| `quantities` 是唯一可寫數量處 | 預算書與報告都由此派生 |
| 預算書工項寫 `"qty_from": "area_m2"`（可加 `qty_factor`） | 數量是算出來的，不是打出來的 |
| 報告數量表 `row_bind` 綁回主檔 | 改主檔，表格數字自動跟著改 |
| `case_core.consistency()` | L×W=A、A×t=V 等關係不符即 **error 並中止**，不產任何交付物 |
| unbound 警告 | 提示哪些表格數字沒綁主檔（將來會走鐘） |

### 7.2 用法

```bat
set PYTHONIOENCODING=utf-8

:: 檢查一致性（0 error 才繼續）
python tools/case_package/case_core.py check cases/<案名>/case.json

:: 三軸一起跑（會先自動檢查，有 error 直接中止）
python tools/case_package/case_package.py cases/<案名>/case.json
```

案件資料夾結構與新增案件 SOP 見 [`cases\README.md`](../cases/README.md)。

### 7.3 已驗證：單一案件檔 → 三軸全過

`cases\AC刨鋪5cm工程\case.json` 一道指令產出 **8 個檔案、三軸全部 exit 0**：

| 軸 | 驗證 | 證據 |
|---|---|---|
| 設計圖 | `check_delivery.py` E1~E18 | exit 0；26 棟逐戶建物（SHP 114 年版）、26 Hatch、**0 字高違規**、1:600 標準比例、DWG 137,961 B |
| 預算書 | xlsx 回讀總計＋`gridcraft-cli check` | exit 0；直接工程費 608,195／總計 **777,364 元** |
| 設計報告 | 產檔＋R1~R16 | exit 0；22 頁、850.6／42.5／160.84 與主檔一致 |

同一份案件檔改數量會**同時**反映到三軸（實測：area_m2 850.6→900、volume_m3 42.5→45 時，預算書 02/03 變 900、04 變 103.5 t，報告數量表 7 列同步更新）；只改 A 不改 V 時 `check` 回 **exit 1、2 error**（A≠L×W、V≠A×t），且 `case_package` 連 `out\` 都不產。

### 7.4 類別化數量模型（`quantities.model`）

道路、擋土牆、排水溝的數量結構不同，**不能用同一套公式硬套**。`tools\case_package\qty_models.py` 定義：

| model | 必要輸入 | 主要衍生量 |
|---|---|---|
| `road` | length, width_avg, area, thickness, volume | 採**驗算**（A=L×W、V=A×t，差 >1% 報錯） |
| `wall` | length, height, stem_thickness, base_width, base_thickness | 斷面積、混凝土淨體積、排水孔數、伸縮縫數、模板、開挖、背填、鋼筋 |
| `channel` | length, inner_width, depth, wall_thickness, base_thickness | 斷面積、混凝土體積、模板、開挖、伸縮縫、鋼筋 |

- 算式以**受限 AST 求值**（只允許四則運算與 `ceil/floor/max/min/sqrt/pi`），不執行任意程式碼。
- 規範量直接算進去：排水孔 `ceil(牆面/2)`、伸縮縫 `max(1, floor(L/25))` — 依水土保持技術規範第121條。
- **報告數量表自動生成**：案件沒自備 `report.quantities.items` 時，由模型表格生成 13 列（擋土牆）／5 列（道路），
  數字直接取衍生值並用 `row_bind` 綁定 → 改主檔即同步，沒有第二份可打錯的數字。

### 7.6 尚未涵蓋

- 數量仍要人填 `case.json`（尚未從 DXF 圖層自動量測回填）
- 新增案件仍需人工決定圖幅與比例（`--width/--height/--scale`）
- **斷面圖／配筋圖產線尚未建置**：設計圖軸目前只會做「現況平面圖 A3」；擋土牆／排水溝需要 S-01 標準斷面圖、S-02 配筋圖，尚無工具
- 單價庫僅路面工程 8 項；擋土牆／排水溝單價須自行詢價
