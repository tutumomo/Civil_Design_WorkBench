# 環境需求與自動配置

> 這份文件回答兩個問題：**這個專案需要什麼才跑得起來**、**怎麼讓 AI 幫你一次裝好**。
> 專案本身只用相對路徑（見 `tools/project_paths.py`），資料夾搬到任何磁碟、任何作業系統都能跑；
> 但部分功能要靠外部程式（ArtCraft、AutoCAD、SolidCraft），那些是平台相關的，所以列清楚。
> **macOS 使用者請先讀 §8.5「macOS 專用配置」**（沒有 `*-cli`、沒有 `python.exe`、沒有 AutoCAD）。

## 0. 一句話版本

```bash
python -m pip install -r requirements.txt     # Python 依賴
python tools/project_paths.py                 # 檢查還缺什麼（會逐項列出 OK／—）
```

> **macOS 請在專案內的虛擬環境安裝**（見 §8.5）：
> `python3 -m venv .venv && .venv/bin/python -m pip install -r requirements.txt`，
> 之後所有指令用 `.venv/bin/python`（或設 `CIVIL_AI_PYTHON=.venv/bin/python`）。

`tools/project_paths.py` 是本專案唯一的環境探測入口：它會告訴你 Python 版本、專案根目錄、
規範索引在不在、13 套 ArtCraft 找到幾套、AutoCAD／SolidCraft／Blender／CAD 字體有沒有。

## 1. 必要條件（沒有就跑不動核心功能）

| 項目 | 版本 | 用途 | 沒有會怎樣 |
|---|---|---|---|
| Python | **3.10+（建議 3.12）** | 全部工具 | 無法執行 |
| numpy | ≥1.26 | 設計計算（`tools/design/*`） | 設計軸全掛 |
| ezdxf | ≥1.3 | 產生／讀取 DXF | 出圖軸全掛 |
| matplotlib | ≥3.8 | 圖表、斷面預覽 | 部分出圖與圖表失敗 |
| shapely | ≥2.0 | 幾何運算（範圍、緩衝） | 土方／刨鋪範圍計算失敗 |
| pyproj | ≥3.6 | TWD97 ↔ WGS84 座標轉換 | 現況底圖、地籍套繪失敗 |
| PyMuPDF | ≥1.24 | 讀規範 PDF、`find_tables()` | 規範查詢與公式庫的 PDF 功能失效 |

安裝：

```bash
python -m pip install -r requirements.txt
```

> **不需要**編譯器、不需要 GDAL、不需要任何系統級服務。`pyshp` 取代了 GDAL 的 SHP 讀取。

## 2. 選用但強烈建議（會影響交付品質）

| 項目 | 用途 | 沒有會怎樣 |
|---|---|---|
| **AutoCAD 2020+**（`accoreconsole.exe`）或 **CADCraft CLI** | DXF → **DWG**（交付必須有 DWG）＋ PDF 出圖。CADCraft 可相容 >80% 以上 AutoCAD 功能，並可直接產出 DWG 與出圖 | 若兩者皆無則只能交 DXF，DWG 需另行轉檔 |

| **ArtCraft 15 套** | 見 §3 | 各 App 對應的產出（xlsx／docx／pptx／PDF／3D 材質／逆向重建…）需改用其他方式 |
| **SolidCraft** | 參數化 3D（擋土牆、U 型溝等 3D 模型） | 3D 軸停用 |
| **IngeTrazo 0.6.0** | 3D 建築／土木模型、BIM→IFC4＋數量 CSV、地形剖面、比例 PDF／公尺 DXF；MCP 橋可讓智能體即時建模 | BIM／地形軸停用（其餘產線不受影響） |
| **Blender** | 3D 渲染、旋轉動畫、STL→GLB | 渲染功能停用 |
| **claude-mem**（持久記憶，選用） | 讓 **Claude Code** 跨 session 保留專案脈絡：自動摘要＋MCP 搜尋（`search`／`timeline`／`get_observations`） | 不影響任何產線功能，只是新 session 少了跨次對話的記憶；用法見 [`claude-mem安裝與使用.md`](claude-mem安裝與使用.md) |

路徑都可用環境變數覆寫，不必改程式：

```bash
CIVIL_AI_ROOT      # 專案根目錄（預設＝這個 repo 的位置）
CIVIL_AI_REGS_DB   # 規範索引 sqlite（預設 data/法規/_regs_index.sqlite）
CIVIL_AI_REGS_DIR  # 法規 PDF 目錄（預設 data/法規）
CIVIL_AI_PYTHON    # 要呼叫的 Python 解譯器（預設＝執行中的那一個）
ARTCRAFT_HOME      # ArtCraft 安裝根目錄（預設 C:\Program\ArtCraft）
AUTOCAD_HOME       # AutoCAD 安裝目錄（含 accoreconsole.exe）
SOLIDCRAFT_CLI     # SolidCraft CLI 完整路徑
INGETRAZO_HOME     # IngeTrazo 安裝根目錄（預設 C:\Program Files\IngeTrazo）
INGETRAZO_MCP      # IngeTrazo MCP 伺服器完整路徑（預設 <HOME>\ingetrazo-mcp.exe）
BLENDER            # Blender 執行檔路徑
CAD_FONTS          # CAD 字體庫目錄（預設＝專案內 CAD_FONTS/，已隨 repo 附）
CADCRAFT_FONTALT       # CADCraft：把 SHX 樣式字換成已安裝的 TrueType（只認檔名，如 msjh.ttc）
CADCRAFT_FONTFALLBACK  # CADCraft：缺字時的替代字型（只認檔名；預設會挑到微軟正黑體）
```

`python tools/project_paths.py --json` 會把上述解析結果印成 JSON，方便安裝腳本判斷。

## 3. ArtCraft 15 套（本專案實際用到的）

ArtCraft 是一套桌面創作工具（每套都有 GUI 與 headless CLI）。本專案**一律走 CLI**，
不搶使用者正在操作的視窗。安裝後的路徑慣例是 `<ARTCRAFT_HOME>/<App>/<app>-cli`。

| App | 本專案用來做什麼 | 被哪支工具呼叫 |
|---|---|---|
| **CADCraft** | DXF／DWG／PDF／PNG 轉檔、2D 圖面編修（相容 >80% 以上 AutoCAD 功能，支援跨平台產出 DWG 格式設計圖與出圖） | `tools/a3_sheet/make_sheet.py`、`tools/acad/acc.py` |
| **GridCraft** | 工程預算書 `.xlsx` 產生與回讀驗證 | `tools/boq/boq_build.py` |
| **WordCraft** | 設計報告 `.docx` 產生與轉 PDF | `tools/report/make_report.py` |
| PdfCraft | PDF 合併／抽頁／抽文字／OCR（核對交付件） | 人工或按需 |
| DeckCraft | 簡報（成果說明會） | 按需 |
| PhotoCraft／LightCraft | 現場照片整理（施工照、竣工照） | 按需 |
| VectorCraft／DesignCraft／FigCraft | 標準圖、海報、圖示 | 按需 |
| FilmCraft／EffectCraft／SoundCraft | 成果影片、動畫、配音 | 按需 |
| **TextureCraft** | 3D 模型 PBR 材質貼圖、AO/Normal 烘焙與光追渲染（`.tcraft`、`.glb/.stl`→`.png`） | 銜接 SolidCraft／3D 成果圖 |
| **Craft Anything** | 舊工程程式（`.exe/.dll/.apk/.sqlite`）演算法逆向剖析、網站擷取與潔淨室重建 | 按需 |

**只有前三套（CADCraft、GridCraft、WordCraft）是交付流程的必要條件**，其餘為選用。

驗證：

```bash
python tools/project_paths.py        # ArtCraft 區塊應逐項顯示 OK 與路徑
python tools/selftest/regression.py  # 全案回歸（含預算書與報告軸）
```

## 4. MCP 伺服器（給 AI 智能體用的介面）

本專案預期透過 MCP（Model Context Protocol）把工具暴露給 AI。缺了不會影響命令列，
但 AI 就得改用 shell 呼叫。

| MCP | 用途 | 是否必要 |
|---|---|---|
| `regs` | 規範查詢：`regs_ask`／`regs_search`／`regs_clause`／`regs_formula`／`regs_table` | **建議**（AI 查規範的主要入口） |
| `cindy_memory` | 跨 session 的持久記憶（專案決策、使用者偏好） | 選用 |
| `autocad` | AutoCAD MCP（僅 ezdxf 後端，繪圖操作） | 選用 |
| `ingetrazo` | IngeTrazo 3D／BIM（`run_python`／`query_model`／`screenshot`／`undo`／`redo`）。**stdio 只是橋**：GUI 要開、文件要開、Extensões ▸ AI Bridge (MCP) 要啟動；一次只接一個客戶端 | 選用 |
| `filesystem`／`fetch` | 檔案與網路讀取 | 選用 |

`regs` MCP 的註冊腳本：`python tools/regs/register_mcp.py`（會用 `project_paths.python_exe()`
取得正確的解譯器路徑，不寫死）。

沒有 MCP 也完全可用，等价指令：

```bash
python tools/regs/regq.py "設計一個沉砂池"        # 主題卡
python tools/regs/regq.py --search 擋土牆          # 關鍵字
python tools/regs/regq.py --clause swc_tech 119    # 條文全文
```

### 8.5 macOS 專用配置（2026-11-07 實測建置）

macOS 的三個關鍵差異：**沒有 `python.exe`、沒有 AutoCAD／`accoreconsole`、ArtCraft App 內沒有 `*-cli`**。

#### (1) Python 環境：一定要用專案內 venv

macOS 系統 Python 3.14 為「externally managed」，且**沒有預裝 numpy／ezdxf／matplotlib**；
`regs_server.py` 會在 `import page_assets` 時就因缺 `matplotlib` 而整個服務起不來。

```bash
cd <專案根目錄>
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
./web.sh design          # 會自動優先用 .venv/bin/python
```

> `web.sh` 的 `find_python()` 順序是 `CIVIL_AI_PYTHON` → `.venv/bin/python` → `PATH`，
> 所以建好 venv 後 `./設計工作台.sh` 就會自動用對的直譯器。
> **踩坑**：`web.sh` 的 `print_urls()` 用 GNU grep 的 `-P`，macOS 的 BSD grep 不支援 →
> 會噴 `grep: invalid option -- P`，**不影響服務**，只是少印區網網址。

#### (2) 沒有 `*-cli`：改用控制通道殼層

macOS 的 `/Applications/CADCraft.app/Contents/MacOS/CADCraft` 是 GUI 殼層，
`CADCraft convert a.dxf b.dwg` 會開視窗後直接結束（指令沒跑）。
本專案已內建 `tools/artcraft_cli/` 的三支殼層（`cadcraft-cli`／`gridcraft-cli`／`wordcraft-cli`），
走 ArtCraft 的 JSON-lines 控制通道，**呼叫端（`acc.py`／`boq_build.py`／`make_report.py`）不用改**。
細節與限制見 [`tools/artcraft_cli/README.md`](../tools/artcraft_cli/README.md)。

`tools/project_paths.py` 的 `artcraft_cli()` 會自動找到它們：

```
CADCraft     OK  .../tools/artcraft_cli/bin/cadcraft-cli
GridCraft    OK  .../tools/artcraft_cli/bin/gridcraft-cli
WordCraft    OK  .../tools/artcraft_cli/bin/wordcraft-cli
```

#### (3) 沒有 AutoCAD：不裝 SHX 字型、也能出 DWG

- `tools/install_cad_fonts.py --apply` 會回報「找不到 AutoCAD 字型目錄」——**這是正常現象**，
  macOS 不需要 SHX（CADCraft 不讀 SHX），正式交件仍在有 AutoCAD 的機器上出圖。
- DWG 由 CADCraft 產出，**格式仍是 AutoCAD 2018（檔頭 `AC1032`）**，符合 AGENTS.md §2 契約。
- PDF 出圖的中文會被轉成向量（PDF 抽文字為空），**視覺檢查正常但不可靠 PDF 抽文字校字**。

#### (4) 資料

`data/臺中市建物/臺中市建物_114.7z` 要就地解壓（Homebrew 有 `7z`）：`cd data/臺中市建物 && 7z x 臺中市建物_114.7z`。

#### (5) macOS 上跑完的驗收

```bash
.venv/bin/python tools/project_paths.py                    # 逐項 OK／—
.venv/bin/python tools/regs/verified_selftest.py           # 0 failure(s)
.venv/bin/python tools/selftest/design_launch_check.py --all   # 0 FAIL
.venv/bin/python tools/selftest/regression.py --ignore-new # 11 案基準全相符
```

## 9. 維護工具（清理與重啟）

| 工具 | 用途 |
|---|---|
| `python tools/clean_project.py --dry-run` | 列出可清理的暫存（`_temp/`、評估產物、散落腳本與日誌），先看不刪 |
| `python tools/clean_project.py --apply` | 實際清理並印出回收空間 |
| `powershell -ExecutionPolicy Bypass -File tools/regs/restart_web.ps1` | Windows 重啟規範查詢台（8765）與設計工作台（8766）；只殺「命令列含 `regs_server.py --web`」的行程，不會動到 MCP |
| `./web.sh restart` 或 `bash tools/regs/restart_web.sh` | Linux / macOS 重啟 Web 服務；支援 `./web.sh stop`、`status` |

**`_temp/` 的定位**（AGENTS.md §1.1）：所有機械產物、探測腳本、日誌、中間圖都放這裡，可以整批刪除。
裡面唯一會留下的是 web 服務的日誌（`web8765.log`／`web8766.err` 等），那是執行期佔用的檔案，停掉服務後即可刪。

> 2026-11-02 實測清理：`_temp/` 回收 **1,549 MB**（含 862 MB 的下載套件、185 MB 的虛擬環境、
> 166 MB 的裁圖與快取），另清掉根目錄 25 個一次性腳本、測試輸出與日誌、`_cad_assess/`、
> `_boq_assess/`、19 個 `__pycache__`、以及可重轉的 `_ref/review_崙背/case.dxf`（44 MB）。
> **未動**：`完整案例(參考用)/`、`cases/`、`data/`、`標準圖圖庫/`、`_ref/components_dxf/`、
> `out/` 內的案件交付物與簡報、`tools.excel/`、`標準圖圖庫/A3圖框.dwt`。
