# 規範查詢台

> 用途：使用者說「要設計一個沉砂池」時，**人或 AI 一個動作**就能列出該引用哪些條文、要先算什麼、有哪些數值限制，並附原文摘錄與出處。
> 建立：2026-10-29。資料：`data\法規\` 內 34 部法規／規範（清單見 [`法規庫總目錄.md`](法規庫總目錄.md)）。

## 1. 三個入口，同一個查詢核心

## 2. 口語怎麼對到主題

1. 整句等於主題名或同義詞 → 該主題。
2. 否則找句子裡出現的主題名／同義詞，**最長的優先**（「擋土牆基礎承載力」→ 淺基礎與承載力，因同義詞「基礎承載」4 字比「擋土牆」3 字長；同長時依主題表順序）；其餘也提到的主題列在卡片的「這句話也提到」。
3. 都沒有 → 關鍵字搜尋；整句 0 筆時先去掉「我要、設計、怎麼、多少…」再搜，仍 0 筆就拆成兩字詞（「鋼筋續接長度」→ 鋼筋／續接／長度…，命中 rc112 §25.5.2.1）。

## 3. 指令列

```bat
set PY=python -E -P -X utf8
%PY% tools\regs\regq.py 設計一個沉砂池            :: 主題卡（口語可）
%PY% tools\regs\regq.py 泥砂生產量 USLE --search  :: 純關鍵字搜尋
%PY% tools\regs\regq.py --clause swc_tech 93      :: 單條全文（法規用條號）
%PY% tools\regs\regq.py --clause airconst110 附表二  :: 附表／附件（也接受「附件-2」）
%PY% tools\regs\regq.py --clause urbanroad113 7.3.4  :: PDF 規範用節號；施工規範如 hwconst112 02742/1.2
%PY% tools\regs\regq.py --topics                  :: 列主題與同義詞
%PY% tools\regs\regs_server.py --web              :: 網頁（--host 0.0.0.0 開給區網，需另開防火牆）
%PY% tools\regs\regs_server.py --mcp              :: MCP（由 AI 程式自動啟動，平常不用手動跑）
%PY% tools\design\design_cli.py list              :: 列 15 個設計計算器
%PY% tools\design\design_cli.py show rc_beam      :: 看輸入範例與限制
%PY% tools\design\design_cli.py run rc_beam rc_beam.json
```

選項：`--all`（含已被取代版次，如 `rc100`、`seis111`）、`--n N`、`--per N`、`--json`。

## 5. 擴充：新增設計主題（最常用，約 3 分鐘）

**不用改程式**，加一筆主題、跑測試就好。用輔助指令最快：

```bat
set PY=python -E -P -X utf8
%PY% tools\regs\add_topic.py --name 農塘 --aliases 蓄水池,農地蓄水 ^
    --scope "農地蓄水、灌溉與滯洪" ^
    --core "swc_tech:55=設置原則,swc_tech:56=開挖式農塘" ^
    --prereq "swc_tech:18=逕流係數,swc_tech:96=滯洪量" ^
    --note "農塘容量依集水面積與逕流量估算" --route "挖一個農塘" --dry-run
```

- 先 `--dry-run` 看每條條文解析到什麼標題；確認後拿掉 `--dry-run` 寫入。
- 指令會自動：檢查條文存在／名稱與同義詞沒被別的主題占用 → 寫 `topics.json` → 在 `exams.json` 加一題考題（預設用核心前兩條）與口語分派 → 跑全套測試。**測試沒過就自動還原兩個檔**。
- `--update` 改既有主題；`--topics`／`--exams` 可指到副本先試（本文件撰寫時已用副本驗證過 農塘 全流程）。
- 網頁與 AI 服務**不用重開**，下一次查詢就生效（每次查詢都重讀主題表）。

手動改也可以：`topics.json` 的 `topics` 加 `name`／`aliases`／`scope`／`core[]`／`prereq[]`／`tools[]`／`notes[]`，再到 `exams.json` 加考題與 `route`，最後 `regq_selftest.py` 必須 exit 0。同義詞不能與其他主題重複。

### 選主題的三個原則

1. 使用者會用「一種設施或一個問題」來問（沉砂池、集水井、跌水），不是按規範章節問。
2. `core` 放「設計時一定要引的條文」，`prereq` 放「要先算或先確認的條文」，`notes` 放數值門檻與本工作區工具的限制。
3. 每加一個主題，至少一題考題＋一句口語 `route`，日後有人改壞會馬上被抓到。

## 5B. 擴充：新增一部規範（需下載與切條，約 15～40 分鐘）

1. `tools\regs\fetch_regs.py` 的 `SOURCES` 加一列：`("代號", "名稱_版次", "file|lawmoj|glrs|glrs_all", URL, "權責機關", "版次說明")`。
   - `lawmoj`：全國法規資料庫法規（依「第 N 條」切）
   - `file`：單一 PDF／docx／html 檔（依節號切）
   - `glrs`／`glrs_all`：內政部法規系統單一附件／多附件（`glrs_all` 會合併多份 PDF）
2. `tools\regs\build_catalog.py` 的 `META` 加一列：`"代號": ("類別", "現行｜需再核版次｜已被取代（留作對照）", "備註")`。沒加會在建索引時被擋下並提示格式。
3. 跑：`fetch_regs.py --only 代號` → `build_index.py` → `index_stats.py`（看缺號與超長條文）→ `regq_selftest.py` → `build_catalog.py`。
4. **驗收**：`regq.py <新主題詞> --search` 要看得到新規範；`--clause 代號 條號` 要有正確標題與頁碼。PDF 規範的切條規則依「節號標題行」判定，若該 PDF 排版特殊（表格頁、多欄），要打開 `build_index.py` 的 `code_units()` 調整分組條件，並用 `index_stats.py` 確認條數合理（例：水保 211 條、耐震 247 條）。

```bat
%PY% tools\regs\register_mcp.py --dry-run   :: 看會改哪些檔
```

## 8. 已知限制

- **PDF 規範的表格與公式會亂**。查到後依 `p.頁碼` 開原 PDF；網頁全文視窗偵測到表格線會提示。
- **全國法規資料庫「本條文有附件」的表格不在索引裡**（如下水道標準第 3 條公式、標線尺寸圖）。
- 關鍵字拆詞是兩字切法，雜訊多；排序靠「命中詞數」壓下去，但仍建議看前幾筆即可。
- `hwdrain107` 第 179 頁參考文獻被誤判為節號；`wind103` 解析不完整，請用 `wind103full`。
- `tools\design\rc_design.py` 引用的仍是 100 年版混凝土規範條號；新舊條號對照未做。
- 主題卡只是「該看哪幾條」；需要數值時切到 `/design` 或呼叫 `design_run`。沉砂池、擋土牆、箱涵、排水、滯洪池、建築樑柱與基礎已有確定性引擎，但現地參數仍須由案件提供。
- `hwdrain107`、`flexpave91` 狀態「需再核版次」，引用前確認是否有新版。
- 網頁預設只開本機；開給區網（`--host 0.0.0.0`）需使用者同意並設防火牆。
