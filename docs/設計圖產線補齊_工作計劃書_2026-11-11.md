1. 出圖能力的唯一來源是 `tools/design/design_section.py` 的 `CAPABILITIES`；前端經 `GET /api/design/section/capabilities` 取得，沒登錄的計算器就沒有可按的按鈕。

### 1.4 盤點中另外發現的問題（與缺口無關，但同屬這條產線）

1. **不支援的計算器在本機也顯示「此版本（雲端／靜態）沒有出圖後端」**。`workbench_web.html` 只看 `sectionCap.supported`，分不出「沒有後端」與「這個計算器還沒做」。使用者在本機看到這句會以為環境壞了。
2. **`docs/工作台設計圖產線.md` 過期**：仍寫 `accoreconsole` 轉檔、Windows 路徑；`design_section._publish()` 的 docstring 也寫「走 accoreconsole」。實際預設後端已是 OpenCADStudio（經 `acc.py`）。
3. **`channel_hydraulics` 出圖有 5 個尺寸不是計算器輸入**（壁厚 0.15、底厚 0.15、長度 100、開挖工作寬與深度各 0.3），`slope_stability` 有 6 個。API 有回 `defaults_used`，但圖上的壁厚是預設值而非設計值，使用者不易察覺。
4. **沒有「每個可出圖計算器都真的出得了圖」的自測**。`design_workbench_selftest.py` 只驗 capabilities 端點與前端字串；`design_launch_check.py` G0～G8 不含出圖。`CAPABILITIES` 登錄錯誤要到使用者按按鈕才會發現。
5. **`box_section` 沒有 `--drafter`**（文件 §7 已列待補）。

2. API 產不出 PDF（`export_pdf` 回 501）；計算書 PDF 只能在 App 內按「Rapport」。
3. 模板輸入欄位是英文變數，與本專案參數的對照必須人工逐欄定義（含單位與定義），不可猜。對錯會得到「兩邊都算對、但不是同一題」的假吻合或假差異。

## 2. 目標與原則

- **目標**：A、B 類 14 個計算器都能在工作台按「產生設計圖」出 DXF／DWG／PDF；C 類明確標示不適用；修掉 §1.4 的五個問題。
- **第二目標（X 系列）**：有 OCSS 模板可對的 12 個計算器都有交叉驗算案例；新圖種上架時，圖上關鍵數值有第二套獨立算法背書。
- **原則**
  1. **數值不得變動**：本計劃只加出圖，不改任何計算引擎；每項完成後 `regression.py` 不跑 `--update` 仍須通過。
  2. **圖上的每個數字都來自計算結果**，不得在繪圖端重算或另給預設；必須用預設值時，圖面說明欄要印出「假設值」。
  3. **沿用既有產線**：`drawing_rules.add_plot_layer()`、`TOMO` 字型、`monochrome.ctb`、A3 圖框、`check_delivery.py`（E1～E18）、`acc.py` 轉檔。不另立一套。
  4. **先找標準圖**：`標準圖圖庫/`（擋土牆、排水溝渠、集水井與消能、附屬詳圖等）與 `_ref/components_dxf/` 有現成圖元者優先引用（`AGENTS.md` §1.1 第 7 點）。
  5. **每新增一種圖，先出一張給使用者目視確認版面**，再往下做同類的其他計算器。自動檢核抓不到「圖讀不懂」。
  6. **交叉驗算的差異要查到原因才下結論**。差異不等於本專案錯：規範版次、假設、係數取法不同都會造成差異。查明後三選一並留紀錄——修本專案引擎（走上架 SOP、另立 commit）、回報 OCSS 模板問題、或登錄為「已知且可解釋的差異」並寫明理由。不得為了通過而放寬容差。
  7. **不動使用者開著的 OCSS 專案**。批次驗算一律用無狀態的 `calc_evaluate`；需要 `sheet_add` 套模板時（會讓專案變「未儲存」且刪回去也不復原），先請使用者開一個空白專案或取得同意。

## 4. 各項細節

### 4.1 D 系列：出圖

**完成紀錄（2026-11-11）**：新增 `tools/crosscheck/ocss_inventory.py`（開始前確認專案無工作表，`sheet_add`→讀→`sheet_remove` 一律 finally 移除；跑完工作表數 0）；17 個 `tw-*` 模板的原始盤點存 `tools/crosscheck/maps/_inventory/`；X2 四個目標（懸臂牆、重力牆、排水溝、箱涵）有對照草稿 `tools/crosscheck/maps/<模板>.json`，標 `draft-未經試算驗證`，每份列出 blockers。

盤點發現（影響 X1）：
1. **模板有兩種輸入方式。** `prompt` 型（`?{預設}`，如懸臂牆、梁、柱、基腳）：`evaluate(source, values={...})` 可直接覆寫（實測 H_wall 5→6 生效）。`literal` 型（`B_chan = 0.60'm`，如排水溝、箱涵、重力牆、沉砂池、水面線、樓版、樁帽）：`values` **無效**（實測 B_chan 不變），X1 必須改寫 source 該行。17 個中 literal 有 8 個。
2. **UC 只是需求／容量比值**，不是 FS。比 FS 要先查 OCSS 該 UC 的容許值定義，或改讀輸出變數。重力牆只有 `UC_max` 一項，只能讀輸出變數。
3. **差異比預期大，已列在各 map 的 blockers**：OCSS 懸臂牆無被動土壓與凝聚力、有 `mu_base` 輸入；OCSS 箱涵只有單孔、車載模型不同、配筋為輸入而非引擎選配；排水溝模板含合理化公式與結構檢核。因此 X2 不是「灌值比對」，每項都要先對齊假設，工作量上調為「中」。
4. 懸臂牆輸入是否全對得上尚未驗證：`mu_base`、頂厚 `t_top` 本專案的對應待查引擎。

#### X1　交叉驗算工具擴充

- 現況：`checks/*.json` 只支援「一段手寫計算文字 ↔ 一個函式回傳值」的一比一比對。

**完成紀錄（2026-11-11）**：新增 `tools/crosscheck/ocss_template_check.py`；`ocss_crosscheck.py checks` 支援 `type: "template"` 案例（`ours`／`ocss` 路徑語法、`reciprocal`、容差、處置三選一規則）。灌值同時支援 prompt 型與 literal 型；模板原始碼來自盤點存下的 `maps/_inventory/*.cpd`，完全不動 OCSS 專案。新增 `tools/selftest/ocss_template_check_selftest.py`（假客戶端，21 項，不需桌面程式），納入 `run_all.py` 為 `ocss-template`。沿用 `unit_warnings()`。仍不進預設流程。

**第一個案例（懸臂牆 ↔ `tw-retaining-wall`）的結果與發現**：Ka 與土壓 Pa 吻合到 1e-5 量級；傾倒力矩差 1.2%（本專案 158.11、OCSS 160.03 kN·m/m），已查到原因，**不是容差問題，是引擎範圍**：`retaining_wall.analyse()`（懸臂式、重力式走這條）
1. 土壓只算到 `height_m`（牆身高，不含底版厚），傾倒力臂寫成 `BT + H/3`；OCSS 與常見做法對總高（含底版）算虛擬牆背土壓。
2. **完全不計超載**：`analyse()` 沒讀 `surcharge_kpa`（只有 `_analyse_semigravity` 路徑讀）。把 `soil.surcharge_kpa` 設 10 對結果毫無影響。

影響：超載與底版厚都會讓土壓變大，所以本專案算出的滑動、傾倒、承載 FS 會偏高（偏不安全側）。**這是設計變更，會動 11 案回歸基準，屬 ask-first，已停下等使用者決定**，本次沒改引擎。案例中傾倒力矩項刻意不寫處置，維持失敗，直到決定修正或另有說明。

## 7. 需要使用者決定的事項

1. **優先順序**：§5 以「本業主力先做」排序。若建築樑柱與基礎的案量較多，階段三可提前。
2. **圖號慣例**：本檔暫用 B-01／C-01／F-01／P-01／ST-01／A-01／D-03～D-05，是否有公司既定的圖號規則？
3. **`drainage_network` 要示意圖還是真實平面圖**：後者需先加節點座標輸入。
4. **`sediment_basin`、`foundation_pile` 的引擎資料不足以畫完整構造圖**（缺池壁型式、樁帽尺寸）：先出受限的配置圖，還是先擴充計算器？
5. **`hydrology` 標「不適用」**是否同意，或希望出成果圖表（如降雨強度—延時曲線）？

6. **X0 需要你在 OCSS 開一個空白專案**（盤點模板欄位會新增再刪除工作表，不想動到你正在用的專案）。
7. **交叉驗算的容差**：現有案例用相對 1e-5（同公式不同實作）。模板對照因係數取法可能不同，建議檢核值（FS、UC）先用相對 1%，超過即查原因；是否同意？

## 8. 不在本計劃範圍

- 雲端（Cloudflare 靜態版）出圖：沒有 Python 後端，維持顯示「請於本機執行」。
- 翼牆、端牆、施工階段、搭接與錨定施工詳圖（`docs/工作台設計圖產線.md` §7 既有限制）。
- 平面配置類圖說（現況平面圖、地籍套繪圖）：已有獨立產線。
- 任何計算引擎的數值邏輯變更（D5、D12 若需擴充輸入或輸出，或 X 系列查出引擎錯誤，各自另立 commit 並走上架 SOP）。
- 把 OCSS 放進 CI 或每次出圖的必經流程（無 headless 模式）。
- 用 OCSS 取代本專案引擎：權威數值仍是 `tools/design/`（有回歸基線），OCSS 是第二套獨立算法與可稽核計算書。
