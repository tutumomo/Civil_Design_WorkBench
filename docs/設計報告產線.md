# 設計報告產線（tools/report）

> 三大交付之一：**設計報告**。輸入一份案件 JSON，輸出 A4 中文設計報告 `.docx` ＋ `.pdf`。
> 文件性質＝**設計輔助文件**，不是技師簽證文件；報告內固定包含「正式施工前須由合格技師依實際地勘覆核簽證」聲明。
> 建立日期：2026-10-28　｜　端到端實測：`_report_test/AC刨鋪5cm工程_設計報告.docx`／`.pdf`（22 頁，驗證 16 項 0 錯誤）

---

## 1. 產線在整體架構中的位置

```
案件資料 JSON ──┬─→ tools/site_basemap ＋ tools/a3_sheet ──→ A3 圖說（dwg/dxf/pdf/png）
                ├─→ tools/boq/boq_build.py ───────────────→ 預算書（xlsx/pdf）
                └─→ tools/report/make_report.py ──────────→ 設計報告（docx/pdf）  ← 本產線
                                                             ↑
                                           templates/report/（版面＋14 章骨架＋法規庫＋聲明稿）
```

三軸共用同一份案件 JSON，**同一組數量不得互相矛盾**；本產線會在附錄 C 自動做數量一致性複核（V＝A×t、A＝L×W，容許差異 1%）。

---

## 2. 快速開始

```bat
set PYTHONIOENCODING=utf-8
cd /d <專案根目錄>

REM 產製（docx＋pdf）
python tools/report/make_report.py ^
  --case tools\report\examples\AC刨鋪5cm工程.json ^
  --out-dir _report_test

REM 交件前回讀驗證（R1～R16，退出碼 0 才算完稿）
python tools/report/verify_report.py ^
  "_report_test\AC刨鋪5cm工程_設計報告.docx" ^
  --pdf "_report_test\AC刨鋪5cm工程_設計報告.pdf"
```

輸出（檔名主幹＝`<工程名稱>_設計報告`）：

| 檔案 | 說明 |
|---|---|
| `<工程名稱>_設計報告.docx` | 目錄與頁碼**已烘焙**（不是空目錄，開檔即可看目錄、免按 F9） |
| `<工程名稱>_設計報告.pdf` | A4 版面，標楷體／新細明體**已嵌入** |
| `<工程名稱>_設計報告_產製報告.json` | 章節狀態、待補清單、表號圖號數、外部指令與耗時（供自動化／稽核用） |

### 參數

| 參數 | 預設 | 說明 |
|---|---|---|
| `--case` | （必填） | 案件資料 JSON |
| `--out-dir` | `_report_test` | 輸出目錄（不存在會自建） |
| `--template-dir` | `templates/report` | 範本目錄 |
| `--wordcraft` | 自動偵測 | `wordcraft-cli.exe` 路徑（亦可用環境變數 `WORDCRAFT_CLI`） |
| `--no-pdf` | 關 | 只產 `.docx` |
| `--no-wrapper` | 關 | 不呼叫外部轉檔（只產未展開目錄的初稿，供離線除錯） |
| `--keep-raw` | 關 | 保留 `_raw.docx`（未展開目錄的初稿） |
| `--fail-on-placeholder` | 關 | 仍有「需人工補」時以退出碼 1 結束（CI／交件門檻用） |
| `--allow-placeholder` | 關 | **放行「案名／主辦機關未確認」**（內部測試用；交件前不得使用） |

### 2.1 輸出前的確認閘門（公司規範，不可略過）

**報告書輸出前必須先向使用者確認「案名」與「主辦機關」**，所以 `project.full_name` 與
`project.agency` 不得空白、也不得含「待填／請填／待確認／TBD」等字。任一不合格時：

```
✗ 報告書輸出前必須先向使用者確認案名與主辦機關（公司規範）：
    · 主辦機關：（主辦機關待填）
→ 退出碼 4，完全不產檔
```

內部測試（回歸、示範案件）請加 `--allow-placeholder`：封面該欄會以**深紅字**顯示
「【需人工補｜封面】主辦機關」，並在產製報告的 `warnings` 與附錄 B 留下「此檔不得直接交件」。
`case_package.py` 同名參數會轉送給報告軸；`tools/selftest/regression.py` 已內建放行（示範案件多為待填）。

### 退出碼

| 碼 | 意義 |
|---|---|
| 0 | 成功 |
| 1 | 產製或轉檔失敗（或指定 `--fail-on-placeholder` 且仍有待補項） |
| 2 | 案件 JSON 不足（缺 `project.name`）或 JSON 格式錯誤 |
| 3 | 找不到 `wordcraft-cli` |
| 4 | **案名／主辦機關未確認**（公司規範；`--allow-placeholder` 可放行） |
| 130 | 使用者中止 |

## 3. 輸入 JSON schema

必填僅 `project.name`；其餘缺漏**不會失敗**，而是變成報告內的「需人工補」佔位符（黃底）並彙整到附錄 B。

### 3.1 基本資料

| 欄位 | 型別 | 說明 |
|---|---|---|
| `project.name` | str | **必填**。工程名稱（同時作為輸出檔名主幹） |
| `project.full_name` | str | 全銜（頁首、**封面案名**用）；省略時沿用 `name` |
| `project.agency` | str | **主辦機關（封面必填，見 §2.1）**；空或含「待填」→ 退出碼 4 |
| `project.code` | str/null | 計畫編號（封面不顯示，僅供他處引用） |
| `project.category` | str | 工程類別：`道路`／`排水溝`／`擋土牆`／`邊坡`。**決定第 6、7、8、11 章為「不適用」或「需人工補」** |
| `project.location` | obj | `{county, town, village, section, lot, desc}`；`desc` 優先 |
| `project.crs` | obj | `{name, epsg, unit}`，如 `TWD97 TM2 二度分帶／EPSG:3826／公尺` |
| `project.coords` | list | `[{name, E, N, lat, lon}]`，供他軸對照 |
| `project.client` | str/null | 委託單位（封面不顯示；主辦機關請填 `agency`） |
| `project.designer` | str | 設計單位／設計者（**封面固定印「設計監造單位：穀山技術顧問有限公司」**，改 `style.json` 的 `cover.design_unit`） |
| `project.reviewer` | str/null | 審核者（本產線不產生簽證欄位） |
| `project.date` / `version` | str | 產製日期、報告版次 |
| `report.title` | str | 報告名稱，預設「設計報告書」 |
| `report.subtitle` | str | 封面副標（可省略） |
| `report.code_label` | str | 封面編號欄標籤，預設「計畫編號」 |

### 3.3 三種子結構

**table（表格）**

```json
{
  "caption": "工程數量表",
  "columns": ["項目", {"name": "數量", "width_cm": 2.7, "align": "center"}],
  "rows": [["全線長度 L", "160.84", "m", "沿設計中心線實測"]],
  "note": "本表為設計數量，未含損耗。",
  "width_cm": 15.5
}
```
* `caption` 省略時用該區塊的 `label`；表號由產生器自動編（**表 1、表 2…**）
* 欄寬未給時平均分配；`align` 預設第一欄 left、其餘 center
* 儲存格文字可用 `\n` 換行；表頭跨頁自動重複

**check（檢核判定）**

```json
{"item": "滑動（常時）", "requirement": "FS ≥ 1.5（水土保持技術規範第 120 條）", "value": "FS = 1.72", "verdict": "合格"}
```
自動排成「檢核項目／規範或設計要求／計算或實測值／判定」四欄。

**figure（圖）**

```json
{"path": "AC刨鋪5cm工程/AC刨鋪5cm工程_平面配置圖_A3.png", "title": "設計平面配置圖（S=1/700）", "note": "check_delivery.py 退出碼 0", "width_cm": 15.5}
```
路徑解析順序：絕對路徑 → 案件 JSON 同層 → 上一層 → **工作區根目錄**（故可用 `AC刨鋪5cm工程/…` 相對寫法）。圖檔不存在 → 出佔位符，不會失敗。

> 「不適用」之章節**不另起新頁**，避免出現整頁只有一行字的空白頁；仍保留章標題並說明保留原因（維持 14 章結構完整）。

### 「需人工補」佔位符

資料缺漏時在該處插入：

```
【需人工補｜章名】項目名稱        ← 黃底粗體
    說明：要補什麼、依哪條規範、為什麼不能自動產生
```

同一份清單會彙整到 **附錄 B**，並在 `產製報告.json` 的 `placeholders` 陣列逐條列出（含所屬章節與說明），可直接派工。

## 6. 範本檔（`templates/report/`）

### 法規引用機制

* `basis.regulation_ids: ["SWH-120"]` → 自動排「引用法規一覽表」＋條文原文＋適用說明
* `regulations.json` 每條有 `verified: true/false`；`false` 者一律顯示「版次待核」並自動加一段提示（`boilerplate.reg_unverified`）
* **已查證**：水土保持技術規範第 117、118、119、120、121 條（114.05.07 修正，查證日 2026-10-27，來源 `law.moa.gov.tw`）
* **版次待核**：市區道路及附屬工程設計規範、公路工程施工規范、建築物基礎暨設計規範、建築物耐震設計規範 → 引用前必須人工核對條號與版次

## 7. 交件前驗證（verify_report.py）

```bat
python tools/report/verify_report.py <docx> [--pdf <pdf>] [--pages 1,2,7] [--strict]
```

| 項 | 檢核 | 判準 |
|---|---|---|
| R1 | DOCX 可重開 | python-docx 能解析 |
| R2 | 14 章齊全且順序正確 | 章次 == 1..14 |
| R3 | 表號連續無跳號 | 表 1..N |
| R4 | 圖號連續無跳號 | 圖 1..N |
| R5 | 頁首含工程名稱、封面頁首空白 | 文字比對 |
| R6 | 頁尾含 PAGE／NUMPAGES 欄位 | XML 欄位比對 |
| R7 | 含技師覆核／簽證聲明 | 全文比對 |
| R8 | 文件資訊量足夠（防空殼） | 全文 > 6,000 字元 |
| R9 | PDF 頁數合理 | ≥ `--min-pages`（預設 3） |
| R10 | 中文字型已嵌入 | 字型表含 Ming／Kai／DFKai |
| R11 | 中文正常無方塊 | 中文字元佔比 ≥ 20%、U+FFFD 與 □ = 0 |
| R12 | 無整頁空白 | 每頁版心著墨 > 0.2% |
| R13 | 目錄已展開含頁碼 | 目錄頁 ≥ 10 條章節行 |
| R14 | 表格框線存在 | 向量線段物件 ≥ 100 |
| R15 | 內嵌圖片存在（警告） | 圖片物件 ≥ 1 |
| R16 | 各章標題在 PDF 文字層可讀（警告） | 逐章比對 |

驗證同時把指定頁轉 PNG（`_verify/_verify_png/`）供**目視檢查**，並輸出 `_驗證結果.json`。退出碼 0 = 無錯誤。

> AGENTS.md §3「完稿重開驗證」落實：寫檔成功 ≠ 可用，本產線要求 **R1～R16 全過 ＋ 人工目視 PNG** 才宣稱完成。

## 9. 已知限制（誠實聲明）

1. **不產生簽證欄位**：封面與第 14 章只有「簽收／覆核」說明，沒有技師簽章欄與圖記；正式文件須另行加蓋。
2. **PDF 由 `wordcraft-cli` 轉檔**：若環境無此工具，只能產 `.docx`（退出碼 3），目錄需在 Word 內按 F9 更新。
3. **目錄樣式靠 TOC 1／TOC 2 樣式命名**：若日後轉檔器改用其他樣式名，目錄中文可能落回轉檔器內建日文字型（實測已用預先定義樣式修正，需回歸 R10／目視確認）。
4. **無圖表目錄（List of Tables／Figures）**：目前只做章節目錄；需要時須擴充 docx_build。
5. **表格不支援合併儲存格、巢狀表、跨欄**；複雜版面請在 Word 手動調整後另存。
6. **圖片為靜態嵌入**：不會自動把 DXF／PDF 轉 PNG；須先用 `tools/a3_sheet` 產出 PNG 再填入 `drawings.figures`。
7. **數量一致性只複核 V＝A×t 與 A＝L×W** 兩式；其他數量（如鋼筋、模板）不會自動驗算。
8. **Word 未實測**：轉檔以 `wordcraft-cli`（LibreOffice 系）驗證通過；`.docx` 曾以 python-docx 重開通過，但**未在 Microsoft Word 實機開啟**確認無「修復」提示（OOXML 元素順序已依 schema 以 canonical order 插入以降低風險）。
9. **未支援多語／英文版報告**；亦未產生業主格式（如公共工程委員會格式）之專屬版式。
10. **法規庫僅水土保持技術規範 5 條為已查證原文**；其餘 4 部規範為「版次待核」佔位，引用前必須人工核對。

## 10. 疑難排解

| 症狀 | 原因 | 處理 |
|---|---|---|
| `✗ 案件資料不足：缺少 project.name` | JSON 缺工程名稱 | 補 `project.name`（輸出檔名也靠它） |
| `⚠ 建議先 set PYTHONIOENCODING=utf-8` | 未設環境變數 | `set PYTHONIOENCODING=utf-8`（AGENTS.md §3） |
| 退出碼 3、無 PDF | 找不到 `wordcraft-cli` | 指定 `--wordcraft` 或設 `WORDCRAFT_CLI` |
| 目錄空白／顯示「將於產製時自動更新」 | 轉檔未執行 `--update-fields` | 確認退出碼 0；或開 docx 按 F9 |
| 某章整章黃底佔位符 | JSON 無該章資料 | 補 JSON 或依附錄 B 人工補件 |
| 第 6/7/8/11 章顯示「不適用」 | `project.category` 非擋土牆／邊坡／排水溝 | 若確有該類構造，改 `category` 或擴充 `applies_to` |
| 圖檔沒出現、變成佔位符 | 路徑解析失敗 | 用絕對路徑，或以工作區根目錄為基準的相對路徑 |
| PDF 中文變方塊 | 系統缺標楷體／新細明體 | 確認 `C:\Windows\Fonts\kaiu.ttf`、`mingliu.ttc` 存在 |
