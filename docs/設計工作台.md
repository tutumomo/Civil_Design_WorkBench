# 工程設計工作台（統一計算入口）

> 建立：2026-10-29
>
> 目的：讓使用者用口語指定工項後，AI 能先查規範、再呼叫確定性引擎計算，最後把
> 檢核值、限制、規範依據與可追溯紀錄帶回對話或交付流程。

## 1. 三個入口，同一個計算核心

| 入口 | 位置 | 用途 |
|---|---|---|
| 網頁 | `http://127.0.0.1:8765/design` | 人可直接改參數、執行、看檢核表與下載 JSON |
| 指令列 | `tools\design\design_cli.py` | AI 或批次作業使用 |
| MCP | `design_list`／`design_show`／`design_run` | Codex、Claude 等智能體直接呼叫 |

三者都呼叫 `tools\design\design_api.py`，公式只在各專業引擎內執行，不在聊天或 UI
重寫。每次預設保存到 `out\design_workbench\runs\`。

啟動網頁：

```powershell
$env:PYTHONIOENCODING='utf-8'
C:\Python312\python.exe -E -P -X utf8 tools\regs\regs_server.py --web
```

或啟動指令：
- **Windows**：雙擊根目錄 `設計工作台.bat`
- **Linux / macOS**：執行 `./設計工作台.sh` 或 `./web.sh design`（支援 `status`、`stop`、`restart`）

## 3. 指令列

```powershell
$env:PYTHONIOENCODING='utf-8'
$PY = 'C:\Python312\python.exe'

& $PY -E -P -X utf8 tools\design\design_cli.py list
& $PY -E -P -X utf8 tools\design\design_cli.py show rc_beam
& $PY -E -P -X utf8 tools\design\design_cli.py run rc_beam rc_beam.json
```

`run` 不加 `--no-persist` 時會保存完整結果。退出碼 `0` 是全部設計檢核通過；
`1` 是計算完成但有未通過項；`2` 是輸入／命令列錯誤。

## 4. 口語操作範例

| 使用者說 | 應呼叫 |
|---|---|
| 「檢核 3 公尺懸臂式擋土牆」 | `wall_stability` |
| 「設計三孔 3×2.5 公尺箱涵」 | `box_culvert` |
| 「這條排水溝 0.5 cms 夠不夠」 | `channel_hydraulics` |
| 「排水系統這幾段會不會滿管」 | `drainage_network` |
| 「滯洪池容許出流 0.8 cms」 | `detention_basin` |
| 「幫我配三層樓 RC 樑柱」 | `building_frame` |
| 「柱腳垂直載重 1000 kN，要多大獨立基腳」 | `foundation_isolated` |
| 「相鄰柱沉陷不一樣，角變量會不會太大」 | `settlement_assessment` |
| 「這條坡面 25 度會不會滑」 | `slope_stability` |
| 「這支鋼柱柱腳要多大、幾支錨栓才夠」 | `steel_column` |
| 「淨寬 60 cm 的明溝要加蓋，重車會過」 | `channel_cover` |

AI 的正確順序是：

1. 用 `regs_ask` 查適用規範與前置計算。
2. 用 `design_show` 看必要輸入與限制。
3. 缺的現地參數只問會改變結果的項目。
4. 用 `design_run` 計算，不自行心算替代。
5. 回報未通過項、限制、參數來源與是否已保存紀錄。

## 6. 擴充方式

**完整流程見 [`docs\設計計算器上架SOP.md`](設計計算器上架SOP.md)**（需求確認 →
不確定先問 → 引擎實作 → 串接 `design_api` → 條文與主題卡 → 測試 → 上架驗證 → 文件回報）。
八道關卡以 `tools\selftest\design_launch_check.py <id>` 一鍵檢核，0 FAIL 才算上架：

```powershell
& 'C:\Python312\python.exe' -E -P -X utf8 tools\selftest\design_launch_check.py --all
```

摘要版（細節仍以 SOP 為準）：

1. 先找可重用的 `wall_geometry.py`、`earth_pressure.py`、`frame_analysis.py`、
   `load_combinations.py`、`rc_design.py`、`foundation_design.py`、`hydrology.py`。
2. 新增專業引擎，提供 `analyse()`／`format_report()`／`example_payload()`／`selftest()`、手算例與限制。
3. 在 `design_api.py` 建 `_run_<id>()`、加入 `RUNNERS` 與 `CATALOG` 範例（含 `field_rules`，列舉一律 select）。
4. 在 `tools\regs\verified\_links.json` 連結已驗證條文，並在 `tools\regs\topics.json` 加主題卡（漏這關口語查詢會查不到）。
5. 跑 `design_core_selftest.py`、`design_workbench_selftest.py`、`regq_selftest.py`、全案 `regression.py`，最後跑 `design_launch_check.py`。

工作台會依 `CATALOG` 範例自動產生表單，所以只要新計算器的範例是完整 JSON，
不必另外改前端；但要補 `workbench_web.html` 的 `LABELS`／`NUMERIC_HINT`，否則欄位標籤是英文鍵名。

### 6.1 欄位規則與擋土牆高度限制

`CATALOG` 可用 `field_rules` 描述欄位型別、選項與連動限制；`list_calculators()` 會把
這份規則帶到網頁與 MCP，前端再依規則產生下拉選單、提示與送出前檢核：

```json
{
  "wall_type": {
    "type": "select",
    "choices": [
      {
        "value": "gravity",
        "label": "重力式（有效高 ≤ 4.0 m）",
        "defaults": {"stem_thickness_m": 0.45, "base_width_m": 1.8}
      },
      {
        "value": "semigravity",
        "label": "半重力式（有效高 ≤ 4.0 m）",
        "defaults": {
          "top_width_m": 0.3,
          "base_width_m": 2.5,
          "base_thickness_m": 0.8,
          "front_batter_ratio": 0.3,
          "toe_projection_m": 0.5,
          "toe_soil_depth_m": 1.5
        }
      },
      {
        "value": "cantilever",
        "label": "懸臂式（有效高 ≤ 8.0 m）",
        "defaults": {
          "stem_thickness_m": 0.35,
          "base_width_m": 1.95,
          "base_thickness_m": 0.36
        }
      }
    ],
    "on_change": "rerender",
    "clear_on_change": [
      "stem_thickness_m",
      "base_width_m",
      "base_thickness_m",
      "top_width_m",
      "front_batter_ratio",
      "back_batter_ratio",
      "toe_projection_m",
      "toe_soil_depth_m"
    ]
  },
  "height_m": {
    "type": "number",
    "step": 0.1,
    "max_by": "wall_type",
    "limits": {
      "gravity": {"max": 4.0},
      "semigravity": {"max": 4.0, "input_offset_by": "base_thickness_m"},
      "cantilever": {"max": 8.0}
    }
  }
}
```

切換牆型時，工作台會先清掉舊牆型專用欄位，再套用新選項的 `defaults`，所以不會留下
半重力式缺少頂寬、或懸臂式錯用厚牆參數的半套表單。

擋土牆上限依《水土保持技術規範》第 118 條，以**露出地面的有效高**判定：

| 牆型 | 有效高上限 | `height_m` 的意義 |
|---|---:|---|
| 重力式 | 4.0 m | 牆高即有效高 |
| 半重力式 | 4.0 m | 含底板總高；有效高＝`height_m - base_thickness_m` |
| 懸臂式 | 8.0 m | 牆身露出高度；底板厚另計 |

因此半重力式的輸入上限是 `4.0 m + 底板厚`。後端 `retaining_wall.py` 仍會依實際幾何
重算有效高並拒絕超限，不能只靠前端。要新增牆型時，先在 `WALL_TYPE_SPECS` 加規格，
再確認 `wall_geometry.py` 能建立該斷面；下拉選項與 API 限制會自動產生。

`block_wall`（疊砌式牆）同樣用下拉選單選牆型，限制依第 118 條：

| 牆型 | 限制 | 備註 |
|---|---|---|
| 蛇籠 | 有效高 ≤ 4.0 m | 可逐層給 `layers`，或用層數／層高／底寬／每層退縮自動產生 |
| 格籠 | 每層 ≤ 3.0 m、總高 ≤ 6.0 m | `course_height_m` 前端上限 3 m |
| 漿砌石 | 有效高 ≤ 4.0 m；牆面坡 n ≥ 0.3；高度 ≤ 6.5 倍石材長徑 | `height_m` 上限＝4 m＋埋入深度 |
| 乾砌石 | 同上，但高度 ≤ 5 倍石材長徑 | 同上 |
| 三明治式 | 開挖坡面有效高 ≤ 4.0 m；填方坡面 ≤ 2.0 m（§118 一） | 必選「設置位置」`site_condition`；前端上限隨位置切換 |

扶壁式（`counterfort_wall`）有效高 ≤ 10 m（§118 五，有效高＝牆高－牆前覆土）；加勁式
（`mse_wall`）有效高 ≤ 8 m（§118 六(三)，有效高＝總高－埋入深度），另檢查加勁長度
L ≥ 0.7H 且 ≥ 2.4 m、層距 ≤ 1.0 m。兩者超限皆由後端拒算。

五個擋土牆計算器都可設定**牆趾（牆前）覆土的被動土壓力**：
Pp＝折減比 × ½·Kp·γ·D²，Kp＝tan²(45°＋φ/2)（Rankine）；黏性土另加 2c√Kp·D（僅 `wall_stability`）。
Pp **只計入抗滑**，FS＝(μN＋Pp)／T；傾倒、合力位置與承載都不計（保守）。地震工況沿用靜態 Kp。
只要計入，結果就會警告「覆土須分層夯實且永久不得移除，否則不得計入」。

| 計算器 | D 的來源（一律自基底底面算起） | 引擎預設 | 工作台範例 |
|---|---|---|---|
| `wall_stability` 重力式／懸臂式 | `toe_soil_depth_m` | 不計（`include_passive` 須為 true） | 勾選，D＝0.6 m |
| `wall_stability` 半重力式 | `toe_soil_depth_m` | 計入 | 勾選，D＝1.5 m |
| `block_wall` | `embedment_m`，只算基底，層間不計 | 不計 | 勾選 |
| `counterfort_wall` | `front_soil_depth_m`＋底板厚 | 不計 | 勾選 |
| `mse_wall` | `embedment_m`；γ 取 `soil.foundation_gamma`，未填用 `retained_gamma` | 不計 | 不勾選（FHWA 簡化法通常不計） |
| `anchored_wall` | `front_soil_depth_m`，折減比預設 0.5 | 不計 | 勾選，折減比 0.5 |

折減比欄位是 `passive_ratio`（0～1）。上述預設值維持既有案件的計算結果：既有案件可能帶有
數量模型預設的 `toe_soil_depth_m`，所以重力式／懸臂式不會只因有這個欄位就計入被動土壓。
`include_passive`／`passive_ratio` 放在斷面或 `soil` 區塊都可以，斷面優先。

錨定擋土牆（`anchored_wall`）§118 八只規定適用地區（岩層破碎、節理發達、崩塌、地滑），未訂高度上限；
地錨依《公路邊坡工程設計規範》第六章：

| 項目 | 規定 | 工作台欄位 |
|---|---|---|
| 安全係數（表 C6.4-1） | 臨時性 1.6／2.0／2.0；長久性 2.0／3.0／3.0（抗張材／地層-漿體／抗張材-漿體） | 「地錨類別」下拉 |
| 自由段（C6.7） | 穿過可能滑動面，原則 ≥ 4 m；程式另加 max(1.5 m, 0.2H) 緩衝 | 自由段長 |
| 錨碇段（C6.7） | ≥ 3 m，一般 3～10 m；超過 10 m 只警告 | 錨碇段長 |
| 握裹強度 | 須證明試驗確認；下拉提供土層／岩層參考值，可自填 | 地層-漿體極限握裹 |
| 承壓鈑（C6.9） | 工作荷重下混凝土壓應力 < 0.30 fc' | 承壓鈑邊長 |
| 鎖定荷重（C6.11） | 設計荷重 × 1.10～1.20 | 鎖定荷重／設計荷重 |

地錨深度用逗號輸入（例 `1.5, 3.5, 5.5`）。整體深層穩定（公路邊坡 6.12）不在本計算器內，須另做邊坡穩定分析。

有效高＝總高－`embedment_m`。每一層界面與基底都各取一個自由體檢核（Coulomb 主動
土壓、M-O 地震增量），任一層不過即 NG；牆背懸在填土上、上層懸空或超過高度上限時
直接拒算並說明原因。

### 6.2 曼寧 n 的材料預設與自訂值

`channel_hydraulics` 的 `manning_n` 使用 `number_with_presets` 欄位：左側下拉選單提供
混凝土、塑膠管、漿砌／乾砌塊卵石、草溝與土溝等常用材料範圍，右側數字框則永遠可直接
輸入自訂 n 值。

《水土保持技術規範》第 84 條只規定曼寧公式，**沒有把 n 值固定成單一數字**；第 85 條
則規定不同材料的容許流速。因此工作台把材料與常見 n 範圍作為輸入輔助，不會用選單
鎖死數值，也不會把常用範圍誤標成第 84 條的法定固定值。特殊襯砌、淤積、植生或維護
狀況仍應由設計者選定 n 並在設計紀錄說明依據。

### 6.3 列舉參數一律用下拉選單（2026-10-30）

**硬規則：只要引擎只接受一組固定值，`field_rules» 就必須是 `type: "select"»，不得留給使用者手打。**
自由文字只保留給真正開放的字串：節點／連桿識別碼（`nodes[].id»、`links[].from»）、
逗號分隔的清單（`anchor_depths_m»）、以及數字陣列（`geometry.x_grid_m»、`geometry.storey_heights_m»）。

目前已改為下拉的欄位：

| 計算器 | 欄位 | 選項 | 依據 |
|---|---|---|---|
| `hydrology» | `condition» | 陡峻山地／山嶺區／丘陵地或森林／平坦耕地／非農業使用 | 水保 §18 逕流係數表（只有這五類） |
| `hydrology» | `area_type» | 開發坡面（漫地流 ≤100 m）／集水區（≤300 m） | 水保 §19 |
| `sediment_basin» | `kind» | 臨時性／永久性 | 水保 §92～93（臨時性容量再 ×1.5） |
| `slope_stability» | `stage»、`condition» | 永久性／臨時性 × 平時／地震／暴雨 | 水保 §73 最小 FS 表 |
| `box_culvert» | `cell_count»、`inlet_type» | 1／2／3 孔；8 種進口型式 | 公路排水 §6、附錄 N／O |
| `drainage_network» | `links[].type»、`links[].cell_count» | 明渠／圓管／箱涵／指定容量；1／2／3 孔 | 各斷面所需幾何欄位不同 |

兩個實作細節：

1. **數值型列舉**（如 `cell_count»）的 `choices[].value» 用整數；前端 select 讀回字串後，會依原值型別
   轉回 `Number»，送到引擎仍是 `2» 而不是 `"2"»。
2. **陣列內欄位**用 `path[]» 規則（例 `links[].type»、`footings[].foundation_type»）。前端會把
   `links.0.type» 正規化成 `links[].type» 再查規則；元素皆為純量物件的陣列會自動長成
   「每列一張卡片＋移除鈕＋新增一列」的清單編輯器。含巢狀子陣列的（`settlement.layers»）仍用完整 JSON。

**改完 `design_api.py» 後一定要重啟 `regs_server.py»**：`design_api» 是在請求時才 import，行程啟動後
就留在 `sys.modules»，只重新整理瀏覽器不會載到新規則。症狀是 `python -c» 檢查 catalog 正確、
瀏覽器表單卻是舊的；請直接看 `GET /api/design/catalog» 的 `field_rules» 確認。測試時可另開
`--port 8766»，不要打斷使用者正在看的 8765。

守門：`tools/selftest/design_workbench_selftest.py» 會走訪 22 個計算器的 example，任何字串葉節點
沒有 select 規則、又不在自由文字白名單內就 FAIL；同時檢查上述各欄位的選項內容。

## 7. 目前邊界

- 擋土牆已開放重力式、半重力式、懸臂式（`wall_stability`）與蛇籠、格籠、漿砌石、乾砌石
  、三明治式（`block_wall`）、扶壁式（`counterfort_wall`）、加勁式（`mse_wall`）與錨定式（`anchored_wall`）；
  錨定式的整體深層穩定須另用 `slope_stability` 或專業軟體。
- 箱涵已有附錄 N／O 進口／出口控制、容許上游水深與端牆／翼牆幾何檢核；
  尚未做沖刷深度、低水頭迴水曲線、三維角隅與施工階段。
- 排水網路是穩定尖峰流量，不含儲蓄與時間延遲；單一渠道的迴水／漸變水面線另用
  `channel_profile`（一維標準步法，不處理水躍與側流入流）。
- 滯洪池尚無多峰雨型、閘門、下游迴水與池堤穩定。
- 建築構架是規則 2D、單軸彎矩；未計 3D 扭轉、二階效應、接頭剪力與錨定。
- 獨立／聯合基腳可在提供土層參數時，以分層 2:1 法估算瞬時沉陷；`settlement_assessment`
  另可算正常壓密／過壓密、次壓縮、總沉陷、差異沉陷與角變量。沉陷仍屬幾何篩檢，
  未做土壤—結構互制、側向樁、液化與筏基有限元。
- RC 梁已有垂直箍筋設計，但耐震圍束、扭力、梁柱接頭與彎鉤施工細節仍須技師設計。

因此本工作台是「可追溯的初步設計與檢核工具」，不是可直接蓋章的完整結構設計。

   `document.documentElement.scrollWidth - innerWidth == 0`；抽屜是 `translateX(104%)` 離屏，不算溢出。
